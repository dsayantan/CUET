Question 1Exception Handling
What is the output of the following code?
def check(age):
    assert age >= 0, "Age cannot be negative"
    return age

try:
    print(check(-3))
except AssertionError as e:
    print("Caught:", e)
  1. Caught: Age cannot be negative
  2. AssertionError: Age cannot be negative
  3. Caught: AssertionError
  4. -3
Concept to recallassert condition, message does nothing when the condition is True and raises AssertionError(message) when it is False. It is caught like any other exception; printing the exception object prints its message.
  1. check(−3): the condition −3 >= 0 is False ⇒ AssertionError("Age cannot be negative").
  2. The exception leaves check() before it returns, so the inner print never runs.
  3. The except clause prints "Caught:" followed by e, i.e. the message: Caught: Age cannot be negative.

Answer: option (1) — Caught: Age cannot be negative

TrapAssertionError: … is what an unhandled assertion shows in the traceback; here it is caught, and print(e) shows only the message, not the class name.
Question 2Exception Handling
What is the output of the following code?
def scan(s):
    try:
        n = int(s)
        r = 10 // n
    except ValueError:
        r = -1
    except ZeroDivisionError:
        r = 0
    else:
        r = r + 1
    finally:
        print(r, end=" ")

for s in ["5", "x", "0", "3"]:
    scan(s)
  1. 2 -1 0 3
  2. 3 0 -1 4
  3. 3 -1 0 4
  4. 2 -1 0 4
Concept to recallelse runs only when the try block raised nothing; finally runs every time, after whichever of except/else ran.
  1. "5": 10 // 5 = 2, no exception, so else makes r = 3; prints 3.
  2. "x": int("x") raises ValueError → r = −1.
  3. "0": 10 // 0 raises ZeroDivisionError → r = 0.
  4. "3": 10 // 3 = 3, else → 4. Output 3 -1 0 4.

Answer: option (3) — 3 -1 0 4

TrapForgetting that else adds 1 on the clean runs gives 2 … 3; swapping which except catches "x" and "0" gives 0 and −1 the wrong way round.
Question 3File Handling
Case study: the nursery’s plants.txt program
Ms Sen runs a plant nursery and keeps her stock in a text file plants.txt, one comma-separated record per line. Her son writes the following program for her.
def add_rows():
    with open("plants.txt", "w") as f:
        f.write("Code,Plant,Qty\n")
        f.writelines(["P1,Tulsi,40\n", "P2,Neem,15\n",
                      "P3,Aloe,28\n", "P4,Mint,9\n"])

def low_stock(limit):
    count = 0
    with open("plants.txt", "r") as f:
        f.readline()                    # skip the header line
        for line in f:
            row = line.strip().split(",")
            if int(row[2]) < limit:
                print(row[1], end=" ")
                count += 1
    return count

add_rows() is called first, then low_stock().

Ms Sen wants a new function that adds next week’s plants to plants.txt without losing the lines already in it. Which open() call should that function use?
  1. open("plants.txt", "w")
  2. open("plants.txt", "r+")
  3. open("plants.txt", "x")
  4. open("plants.txt", "a")
Concept to recall"w" truncates an existing file; "a" opens for writing at the end, keeping what is there (and creates the file if absent); "x" fails if the file exists; "r+" writes from the start, overwriting.
  1. Keeping the old lines and adding after them is exactly append mode, "a".
  2. "w" would erase the stock list; "x" raises FileExistsError because the file exists; "r+" starts at offset 0 and overwrites the header.

Answer: option (4) — open("plants.txt", "a")

Question 8Stack
Case study: the hotel parking lane and entry gate
A hotel parks guests’ cars in a narrow dead-end lane that is one car wide: cars enter and leave only through the open end. Cars waiting to be parked line up at the entry gate and are let in in the order in which they arrived. The valet’s app models this as follows.
lane = []          # dead-end parking lane: one opening only
gate = []          # cars waiting at the entry gate

for car in ["K1", "K2", "K3", "K4"]:
    gate.append(car)

def admit():                 # next waiting car drives into the lane
    car = gate.pop(0)
    lane.append(car)
    return car

def release():               # the car nearest the opening drives out
    return lane.pop()
Which pair of data structures does the hotel’s arrangement model?
  1. lane: queue (FIFO); gate: stack (LIFO)
  2. lane: stack (LIFO); gate: queue (FIFO)
  3. both are queues
  4. both are stacks
Concept to recallOne open end for both entry and exit = stack (last in, first out). Join at one end, leave from the other in arrival order = queue (first in, first out).
  1. The lane has a single opening: the last car parked is the first that can leave → stack. The code agrees: append() and pop() on the same end.
  2. The gate lets cars in by arrival order → queue: append() at the rear, pop(0) at the front.

Answer: option (2) — lane: stack (LIFO); gate: queue (FIFO)

Question 10Stack
Case study: the hotel parking lane and entry gate
A hotel parks guests’ cars in a narrow dead-end lane that is one car wide: cars enter and leave only through the open end. Cars waiting to be parked line up at the entry gate and are let in in the order in which they arrived. The valet’s app models this as follows.
lane = []          # dead-end parking lane: one opening only
gate = []          # cars waiting at the entry gate

for car in ["K1", "K2", "K3", "K4"]:
    gate.append(car)

def admit():                 # next waiting car drives into the lane
    car = gate.pop(0)
    lane.append(car)
    return car

def release():               # the car nearest the opening drives out
    return lane.pop()
The lane holds K1, K2, K3, K4, K5 (K1 parked first) and the guest of K2 wants the car. The valet moves the cars in the way into an empty second lane (also one opening only), takes K2 out, and then moves those cars back. How many POP operations are made in all, on both lanes, and what is the main lane’s order afterwards (first parked to last)?
  1. 4 pops; K1, K5, K4, K3
  2. 7 pops; K1, K3, K4, K5
  3. 7 pops; K1, K5, K4, K3
  4. 6 pops; K1, K3, K4, K5
Concept to recallReaching an item below the top of a stack means popping everything above it. Passing items through a second stack reverses them; passing them back reverses them again.
  1. Pop K5, K4, K3 from the lane and push them on the second lane: 3 pops (second lane top is K3).
  2. Pop K2 for the guest: 1 pop.
  3. Pop K3, K4, K5 from the second lane and push them back: 3 pops. Total 3 + 1 + 3 = 7.
  4. They return in the order K3, K4, K5, so the lane reads K1, K3, K4, K5.

Answer: option (2) — 7 pops; K1, K3, K4, K5

TrapCounting only the pops from the main lane gives 4; forgetting the second reversal gives K5, K4, K3.

Case study: the hotel parking lane and entry gate

The valet taps release when the lane is empty, so release() runs lane.pop() on an empty list. What is this situation called, and what does Python do?
  1. Overflow; returns None
  2. Underflow; returns None
  3. Overflow; raises IndexError
  4. Underflow; raises IndexError
Concept to recallUnderflow = trying to pop (or dequeue) from an empty structure; overflow = pushing onto a full one. list.pop() on an empty list raises IndexError: pop from empty list.

TrapA Python list grows as needed, so a stack built on it has no practical overflow.

Question 13Stack
A stack is used to check whether brackets are balanced: every ( is pushed, and every ) pops one (. The string ( ( ) ( ( ) is scanned from left to right. How many items are left on the stack at the end, and what does that show?

Question 15Searching
Which of the following statements about binary search are correct?
  1. It can be applied only to a list that is sorted.
  2. Each unsuccessful comparison discards about half of the elements still being searched.
  3. On a sorted list of 1000 elements it never needs more than 10 comparisons.
  4. For a key stored at index 0, binary search always makes fewer comparisons than linear search.
Choose the correct answer from the options given below:
  1. (A) and (B) only
  2. (A), (B) and (D) only
  3. (B) and (C) only
  4. (A), (B) and (C) only
Concept to recallBinary search halves the search area at each comparison, so it needs a sorted list and at most ⌊log2 n⌋ + 1 comparisons. Linear search finds the first element in 1 comparison.
  1. (A) true: halving makes sense only if the order tells you which half to drop.
  2. (B) true: that is the whole idea.
  3. (C) true: 29 = 512 ≤ 1000 < 1024 = 210 ⇒ ⌊log21000⌋ + 1 = 10.
  4. (D) false: linear search finds index 0 on its first comparison; binary search needs 9 to get there.

Answer: option (4) — (A), (B) and (C) only

TrapBinary search is faster in the worst case, not for every key.
Question 16Searching

Question 17Searching
The function below performs a linear search. What is printed?
def find(L, key):
    for i in range(len(L)):
        if L[i] == key:
            return i
    return -1

L = [4, 9, 2, 9, 7]
print(find(L, 9) + find(L, 5), find(L, 7))
  1. 2 4
  2. 1 5
  3. 0 4
  4. 1 4
Concept to recallLinear search compares from index 0 and returns at the first match; if the loop ends without a match it returns the sentinel −1.

Answer: option (3) — 0 4

Question 19Sorting
Bubble sort (n − 1 passes; pass k compares the first n − k adjacent pairs; no early exit) is applied to [25, 12, 31, 7, 18, 40, 3]. How many comparisons does it make in all?
  1. 21
  2. 42
  3. 49
  4. 6

  2. Total = 6 + 5 + 4 + 3 + 2 + 1 = 7 × 6 / 2 = 21.

Question 20Sorting
Which of the following statements are correct for lists of n elements?
  1. After pass k of bubble sort, the k largest elements are in their final places.
  2. Selection sort makes at most n − 1 swaps.
  3. Insertion sort applied to a list that is already sorted shifts no element.
  4. Insertion sort finds the smallest element of the unsorted part in each pass and swaps it into place.
Choose the correct answer from the options given below:
  1. (A) and (B) only
  2. (B), (C) and (D) only
  3. (A), (B), (C) and (D)
  4. (A), (B) and (C) only
Concept to recallBubble sort carries the largest remaining element to the end in each pass. Selection sort makes one swap per pass, n − 1 passes. Insertion sort shifts an element only while the one on its left is larger.
  1. (A) true: pass 1 fixes the largest, pass 2 the second largest, and so on.
  2. (B) true: one swap (possibly of an element with itself) in each of the n − 1 passes.
  3. (C) true: every new element is already ≥ its left neighbour, so nothing moves.

Answer: option (4) — (A), (B) and (C) only

Trap(D) is selection sort wearing insertion sort’s name.
